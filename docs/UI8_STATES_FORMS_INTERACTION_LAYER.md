# UI-8 — States, Forms & Interaction Layer

## Scope

UI-8 hardens the non-happy paths and interaction layer of ENJAZ UI V2 without advancing the original product roadmap. Phase 4.2 of `ENJAZ_MASTER_ROADMAP.md` remains on HOLD.

Implemented presentation/interaction contracts:
- eight typed exceptional states: loading, empty, error, offline, conflict, permission, success and archived;
- product-level empty search handling;
- reusable textarea/select/form section/action primitives;
- validated Quick Create forms for the currently approved create intents;
- destructive draft clearing through an explicit danger confirmation dialog;
- accessible field labelling, invalid-state signalling and descriptive error binding;
- long Arabic text, large financial value and constrained viewport handling;
- a dedicated UI-8 Chromium journey and visual evidence harness.

## Product integrity

UI-8 does not invent persistence or later-roadmap functionality. Quick Create validates and presents data for review, but clearly states that no record has been saved. Domain/data/auth/Supabase contracts remain outside the presentation layer.

The runtime continues through `src/ui-v2/` only. No `ui-rebirth` presentation dependency is introduced.

## Defects found and fixed during destruction

1. **Strict TypeScript optional-prop mismatch** — `exactOptionalPropertyTypes` rejected `undefined` passed into error props. The form control contract was corrected rather than bypassed.
2. **Legacy gate stage locking** — earlier UI-3/UI-4/UI-6/UI-7 checks assumed an exact historical stage marker. Regression gates were made cumulative so later stages cannot be blocked merely by progression while their original behavior checks remain intact.
3. **Real React form crash after first field edit** — Quick Create retained `event.currentTarget` inside a state updater. After the synthetic event completed, the target became unsafe and the next field disappeared from the browser journey. Values are now captured synchronously before state updates, and UI-8 contains a permanent regression guard against the deferred-event pattern.
4. **Accessibility ambiguity** — fields now expose explicit accessible names plus `aria-invalid`/`aria-describedby` where appropriate, and the browser gate verifies the actual DOM accessibility contract.
5. **Developer terminology leaked into product copy** — manual screenshot review found a visible `UI-8` implementation phrase in the review/extra-action copy after automation was already green. The wording was replaced with normal user-facing language and a runtime guard now rejects stage/developer terminology leakage.
