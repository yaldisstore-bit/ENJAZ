The governing roadmap requires destruction across repeated triggers, stale transitions, conflicting actors, large histories, field offline recovery, intake abuse, branch/team permission boundaries and automation failure isolation.

## Hard scope lock

Phase 8.7 may add tests, probes, diagnostics, regression guards and evidence. It may repair defects exposed by those tests.

It may not create a new product authority in order to make a test pass.

Forbidden unless a discovered defect proves an existing authoritative boundary itself requires a narrowly scoped repair:

- new feature scope;
- new shadow domain stores;
- new write-authority families;
- new generic cross-domain RPCs;
- a second workspace/workforce trust model;
- hidden mutation from presentation components;
- finance mutation from operational destruction tooling;
