# Phase 7.1 — Financial Ledger & Summary

## الهدف

بناء النظرة المالية القانونية الأولى في إنجاز فوق مصادر البيانات المعتمدة أصلًا، دون إنشاء مخزن مالي ثانٍ ودون إدخال أي كتابة مالية قبل Phase 7.2.

## مصادر الحقيقة

- `transactions.current_fee`: الرسم الحالي لكل معاملة غير محذوفة.
- `payments`: الدفعات المسجلة وربطها بالمعاملة والشركة.
- `payment_reversals`: دليل عكس الدفعات.
- `financial_ledger_entries`: القيود الأخرى الداخلة والخارجة.
- `cashbox_accounts`: الأرصدة الافتتاحية للخزائن.
- `companies`: اسم وسياق الشركة المرتبط بالقيد أو المعاملة.

## قواعد 7.1

1. المرحلة **قراءة فقط**. لا إنشاء دفعة، لا عكس، لا تعديل قيد، ولا تسوية ضمن 7.1.
2. الحسابات تتم داخليًا بـ `bigint` على مستوى السنت بعد التحقق من أن قيمة PostgreSQL `numeric(18,2)` وصلت إلى JavaScript بقيمة قابلة للتمثيل الآمن.
3. أي قيمة مالية غير آمنة توقف الملخص `fail-closed` بدل تقريبها بصمت.
4. الدفعة تعتبر معكوسة إذا كانت حالتها `reversed` أو وجد سجل في `payment_reversals`. إذا اختلف المصدران يظهر `paymentIntegrityWarnings` بدل تجاهل التعارض.
5. الدفعات المعكوسة لا تدخل إجمالي التحصيل.
6. الذمة لكل معاملة = `max(current_fee - posted_collected, 0)`.
7. التحصيل الزائد يظهر كرصيد دائن منفصل، ولا يتحول إلى ذمة سالبة.
8. صافي الحركة = التحصيلات الفعالة + قيود الداخل الفعالة - قيود الخارج الفعالة.
9. الرصيد التقديري = مجموع الأرصدة الافتتاحية للخزائن + صافي الحركة.
10. لا يتم الادعاء بأن الرصيد التقديري هو مطابقة مصرفية أو إقفال خزنة؛ ذلك يتطلب مراحل مالية لاحقة واختبارات reconciliation.

## حدود عدم التكرار

Phase 7.1 لا تضيف جداول مالية جديدة. الجداول المالية الموجودة في baseline هي المصدر القانوني. شاشة R2.0-7 القديمة تبقى عينة تصميم في preview فقط؛ التشغيل الحقيقي يستبدلها ببوابة 7.1 المتصلة بطبقة البيانات.
