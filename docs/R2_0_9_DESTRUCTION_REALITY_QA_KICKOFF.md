# ENJAZ Rebirth 2.0 — R2.0-9 Destruction & Reality QA Kickoff

Status: **ACTIVE**

Branch: `r2-0-9-destruction-reality-qa`

Base: `main` after formal R2.0-8 closure and merge.

## Mission

R2.0-9 is the destructive reality gate for the parallel Rebirth 2.0 interface. It exists to discover real failures before legacy eradication, not to generate cosmetic PASS output.

The stage attacks the real browser composition and interaction model at:

- 1280 px
- 430 px
- 390 px
- 360 px
- 320 px

## Required attack classes

- keyboard and focus behavior
- RTL
- mixed Arabic / Latin / numeric content
- extreme long names and unbroken strings
- dense / large presentation sets
- empty-state behavior
- failure / invalid-state behavior
- permission / mutation truthfulness boundaries
- browser Back stack
- direct deep links
- overlay ownership and layering
- landscape / orientation geometry
- reduced motion
- 44 px minimum touch geometry
- horizontal-overflow attacks

## Method

1. **Reproduce before repair.** A discovered failure is recorded as a concrete scenario before code is changed.
2. **No smoke-test substitution.** A source audit cannot replace a browser failure mode when the behavior can be exercised in Chromium.
3. **No fake production claims.** The isolated preview may simulate visual density and malformed content, but it may not claim production persistence or permission authority.
4. **No ad-hoc data channel.** QA must not add fetch/localStorage/sessionStorage persistence to bypass the existing Data Layer.
5. **Cumulative regression remains mandatory.** Golden, Core Work, Records & Relationships, Operational Intelligence, and Zero-Lost stay closed and guarded.
6. **No canonical cutover.** `ui-v2` remains canonical and Phase 5.5 stays locked.

## No-Maze floor

R2.0-8 already closed with 16 / 16 No-Maze scenarios. R2.0-9 must preserve that closure and add destruction scenarios; it may not lower the <= 3 deliberate-action ceiling, introduce hidden primary navigation, duplicate canonical homes, or create back-path failures.

## Exit gate

R2.0-9 may close only when:

- every required attack class has executable evidence,
- every hard width has real Chromium coverage,
- destructive scenario count is at least 15,
- all declared destructive scenarios pass,
- no unresolved browser reality defect remains,
- 44 px touch and horizontal overflow gates pass,
- cumulative Rebirth and business/data gates remain green,
- canonical runtime remains `ui-v2`,
- Phase 5.5 remains locked,
- promotion remains blocked.

Only then may R2.0-10 — Legacy Eradication begin.
