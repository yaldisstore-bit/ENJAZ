# ENJAZ UI Rebirth — Approved Reference Map

This document is the visual reference source of truth for the clean UI generation.

## Global rule

Reference screens control visual composition, geometry, hierarchy, density, navigation treatment, interaction style and motion. ENJAZ domain contracts control business data, labels, actions, permissions and behavior.

The previous ENJAZ visual generations are not design references for this rebuild.

## Approved screen families

### Home / Dashboard
Primary reference: warm yellow + charcoal premium dashboard.
- Bold yellow hero/stat zone.
- Asymmetric project/metric cards.
- Dark focus cards mixed with light surfaces.
- Compact payment/summary rows.
- Integrated bottom navigation with centered action.

### Finance
Primary reference: blue/cobalt finance dashboard.
- Ice-blue canvas.
- Cobalt/deep-navy balance and ledger surfaces.
- Compact finance actions.
- Recent ledger movements.
- Line-chart summaries and trend cards.
ENJAZ content: fees, receipts, receivables, outstanding amounts, expenses, corrections and entity-linked financial movement.

### Analytics
Primary reference: gold + violet + deep navy analytics composition.
- Unequal KPI blocks.
- Progress, line and bar charts.
- Time filters and trends.
- Strong dark analytical focal zone.
ENJAZ content: transaction completion, delay, lawyer/company activity, collection, blockers and cycle time.

### Welcome / Entry
Reference: dark premium welcome / search composition.
- Illustration-led welcome state.
- Dark high-contrast logged-in state.
- Search and compact content cards.

### Workflow / Automation
Reference: staged verification / appointment composition.
- Step progression.
- Circular completion indicator.
- Ordered stages and task state.
- Contextual help/action surface.

### Daily Work / Universal Inbox
References: timeline/date-strip/task planning families.
- Compact date strip.
- Vertical operational timeline.
- Priority/action cards.
- Next-task emphasis.
- Quick-create task/follow-up form.

### Transaction List / Create
Reference: task/project list + create form family.
- Search and filters.
- Compact list/card hybrid.
- Date strip when useful.
- Category/status chips.
- Clean create/edit form with one primary CTA.

### Transaction 360 / Detail
Reference: progression/detail composition.
- Strong top summary area.
- Timeline/activity progression.
- Related people/entities.
- Compact action surface and progress/status visualization.

### Companies / People
References: profile/progress and course/search compositions.
- Search-first discovery.
- Profile hero.
- Relationship/activity cards.
- Progress/context ring where meaningful.

### Operations Center
Reference: project/schedule/control composition.
- Current work cards.
- Schedule/time strip.
- Progress and team ownership.
- Dense operational control without dashboard-card repetition.

### Command Center
Reference: dark high-contrast control composition.
- Executive focal zone.
- Strong primary actions.
- Cross-domain status modules.
- No ordinary stacked list treatment.

### Documents / Vault / Reports
Reference: category/detail/content composition.
- Clear category navigation.
- Search and document summaries.
- Detail screen with metadata and one dominant action.
- Empty/success states may use editorial illustration.

### Notifications / Follow-ups / Inbox
Reference: timeline + compact task list families.
- Priority/state chips.
- Date/time grouping.
- Dense rows rather than oversized cards.
- Strong unread/action-needed hierarchy.

## Shared composition rules

1. Each domain may have its own accent palette, but the app remains one family.
2. Global chrome stays consistent; screen interiors may have distinct compositions.
3. Equal white rounded rectangles are never the default layout primitive.
4. Every screen needs a focal zone and a deliberate information hierarchy.
5. Data-rich screens favor compact rows, charts, chips, timelines and progress indicators.
6. Forms use one clear primary action and avoid visual clutter.
7. Bottom navigation and central action are one engineered composition, not overlapping independent layers.
8. RTL/mobile/safe-area behavior is part of the design, not a later patch.
9. Animation communicates hierarchy and action; it is never decorative noise.
10. No user-facing phase, boundary, proof, audit or developer terminology.
